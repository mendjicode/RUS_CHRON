# Проверки и ограничения

## Итог локальной проверки

Выполнены `npm run check`, `npm run verify:dist`, `node --check electron/main.cjs` и `git diff --check`. Все завершились успешно. Vitest: **55 из 55** проверок в четырёх файлах. Контент: 21 урок, 63 задания, 43 термина, 24 персоналии. Основной текст: 8 114 слов.

Производственная сборка: JavaScript около 1.68 МБ до gzip; PWA перечисляет 11 уникальных ресурсов, включая шрифты, изображение и географию. Осталось предупреждение Vite о крупном JS-пакете и предупреждения Rollup о комментариях в Zod. Они не остановили сборку; сокращение начальной загрузки включено в TODO.

## Проверяемые команды

- `npm run validate:content`: Zod-схемы, уникальность ID, соответствие программе, связанные термины/персоны/места/источники, варианты ответов, наличие текстов по всем эпохам.
- `npm test`: модель повторения, проверка ответов, локальная серия дней, хранение и восстановление IndexedDB через fake-indexeddb, импорт, React SSR всех написанных уроков и основных страниц, взаимодействия через jsdom.
- `npm run build`: TypeScript и производственная сборка Vite/PWA.
- `npm run verify:dist`: наличие локальных ресурсов, включение обязательных файлов в precache и отсутствие конфликтующих ревизий.

В `tests/interactions.test.tsx` проверяются выбор и разбор ответа, множественный выбор, явная самооценка, смена содержания уровней, закладка, заметка, завершение урока и переход к найденному по дате уроку.

## Что эти проверки не доказывают

SSR проверяет создание разметки, jsdom — взаимодействие с компонентами в моделируемом DOM, fake-indexeddb — поведение модели хранения. Ни одно из них не подтверждает визуальный результат настоящего браузера, реальную установку Service Worker или поведение Electron на Windows. Статическая проверка кэша не равна фактической перезагрузке браузера без сети.

Научная проверка не выводится из тестов. Все текущие материалы остаются `written`.

## Ограничение облачной среды этой сессии

Executor: `ccarenv_b64_Y2NhcmVudl81NWM4ZDZmOGFiODg4MTkxOTRiODNkMDdlNTkyYjg0MA`.

`cloud_environment.environment_status` подтвердил подключение и `remote_desktop.enabled: true`, но состояние рабочего стола осталось `unknown`. После готовности среды повторно проверен доступный каталог инструментов: `cua_repl.js`, браузерный инструмент и `open_in_codex` не предоставлены. По правилам managed preview обходной браузер не устанавливался и отдельный preview-сервер не запускался. Поэтому скриншоты и настоящие браузерные тесты не выполнены.

- Устранён конфликт ревизий изображения между общим glob и includeAssets в precache.
- Автоматическая регистрация Service Worker отключена для `file://`; в Electron все ресурсы и так локальны.
- Новый профиль без сохранения не объявляется повреждённым.
- Результаты глобального поиска получили явные доступные названия.

## Ручной контроль при появлении браузера

1. Проверить 1440×900, 1024×768, 390×844; обе темы, размеры текста и клавиатурный фокус.
2. Пройти цикл «каталог → урок → проверка → заметка → закладка → перезагрузка».
3. Собрать production, дождаться готовности кэша, отключить сеть и перезагрузить. Открыть карту, урок другой эпохи, график, шрифты и изображение.
4. Экспортировать JSON, сменить профиль, импортировать; проверить целостность. Некорректный импорт не должен изменять данные.
5. Проверить карту мышью, клавиатурой и сенсорным вводом; всплывающие сведения должны быть доступны без наведения.
6. Пройти сценарий Windows из `docs/WINDOWS.md`.

## Проверка Windows CI

Первый Windows-запуск действительно создал NSIS-установщик, но electron-builder затем попытался автоматически опубликовать релиз и завершился без GH_TOKEN. В `dist:win` добавлено `--publish never`: задача должна только собрать пакет и отдать его как артефакт, без создания релиза и токена публикации.
